## 🌿 Git 工作流与分支规则

### 分支策略

```
master (主分支) ← Wiki.js 只读取这个分支
  ↑
feature/* (功能分支) ← 小虾开发新内容
  ↑
hotfix/* (修复分支) ← 紧急修正
```

### 工作流规范

1. **小虾开发流程**
   ```bash
   # 从 master 创建功能分支
   git checkout -b feature/章节名
   
   # 编辑内容
   git add .
   git commit -m "docs: 添加第X章 XXX"
   
   # 推送到 GitLab
   git push origin feature/章节名
   
   # 创建 Merge Request (MR)
   ```

2. **代码审查 (Code Review)**
   - 所有 MR 必须经过 Owner 或核心成员审查
   - 审查重点：格式规范、双链语法、内容准确性
   - 审查周期：24 小时内响应

3. **合并时机**
   - **最佳时间**：内容完成且通过审查后
   - **避免**：Wiki.js 正在 Import 时合并（可能冲突）
   - **建议**：批量合并，减少 Wiki.js 同步频率

4. **紧急修复**
   - 发现错误时，从 master 创建 `hotfix/描述` 分支
   - 修复后立即合并，不需要等待审查窗口

### 提交信息规范

```
type: 简短描述

- type: docs (文档), fix (修复), refactor (重构)
- 示例: docs: 添加第三章 冷战铁幕内容
```

## ⚡ 快速开始指南（给小虾）

### 5 分钟上手

1. **克隆仓库**
   ```bash
   git clone http://ch4.tailnet-68f9.ts.net/seekkey/wikijs.git
   cd wikijs
   ```

2. **创建分支**
   ```bash
   git checkout -b feature/你的章节名
   ```

3. **复制模板**
   ```bash
   cp 示例_转换格式.md 你的章节.md
   ```

4. **编辑内容**
   - 修改 YAML frontmatter
   - 填充正文内容
   - 添加 `[[双链]]`

5. **提交推送**
   ```bash
   git add .
   git commit -m "docs: 添加XXX"
   git push origin feature/你的章节名
   ```

6. **创建 MR**
   - 去 GitLab 网页创建 Merge Request
   - 等待审查合并

### 文件命名规范

| 类型 | 命名示例 | 说明 |
|------|---------|------|
| 章节 | `chapter-01-1936-1941.md` | 英文+序号，避免中文乱码 |
| 人物 | `person-zhongshan.md` | `person-` 前缀 + 拼音 |
| 事件 | `event-wwii-start.md` | `event-` 前缀 + 英文描述 |
| 概念 | `concept-patent-law.md` | `concept-` 前缀 + 英文描述 |

**注意**：Wiki.js 显示的是 YAML 里的 `title`，文件名只用于内部管理。

### 常见错误

❌ **忘记加 YAML frontmatter** → 页面无法正确显示  
❌ **中文文件名乱码** → 使用英文或拼音命名文件  
❌ **双链语法错误** → 必须是 `[[实体名]]`，不能有空格  
❌ **直接推 master** → 会被拒绝，必须用 feature 分支  
❌ **文件名带空格** → 用 `-` 或 `_` 代替空格
